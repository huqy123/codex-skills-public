# Java / Spring 日常维护

沿用仓库实际 JDK、框架、构建命令和测试设施。先判断数据和控制流程，不因个人偏好升级技术栈或重构无关内容。

## 找到完整业务链路

顺着实际入口核对：

`页面或接口 → 请求对象 → Controller → Service → Mapper/实体/JSON → 数据库 → 重新查询 → 页面、导出或任务`

- 说明字段或规则在哪产生、保存、再次读取和消费。写入正确不代表读取源正确，前端暂时有值也不代表已经保存。
- 核对批量结果是否逐条对应，是否有共享可变对象、上一条残值或最后一条覆盖全部结果。
- 对历史缺字段、JSON 缺键、关联已删除和空值，按业务决定显示、沿用、告警或阻止，不编造默认值。
- 状态、版本和重复打开涉及哪条记录要准确；旧页面保存、并发操作或重复点击不能无条件覆盖新结果。

## 数据访问与失败处理

- 主数据和关联数据批量读取后映射；避免逐条调用数据库或外部接口。大批量读取、深分页和全量导出检查内存与查询次数。
- 普通 SQL 值参数绑定；动态表名、列名、排序仅使用受控白名单。
- 批量更新收紧数据范围；空集合、空条件或错 ID 不能扩大成全表操作。校验记录归属和当前操作资格。
- 多条数据需要一起成功时明确事务；说明部分失败、回滚和重试结果。数据库事务不能覆盖远程系统副作用。
- 历史 JSON 或单条数据损坏时，按需求决定整批阻止还是逐条标识异常，不静默吞错后输出正常外观的错误数据。
- 异常保留原因并指出阶段；日志使用必要稳定标识，不打印凭证、连接串和完整敏感请求。

## 按风险读专项参考

- 并发、线程池、`ThreadLocal`、资源关闭、外部输入或测试分层：读 [专项代码检查](references/code-review.md)。
- 高 CPU、卡死、死锁、线程上涨或内存溢出：读 [JVM 故障排查](references/jvm-diagnostics.md)。诊断工具可能有停顿、磁盘和数据泄露风险，现场采集需单独确认环境与授权。

## 验证不要越级下结论

- 使用仓库已有 Wrapper、CI 或说明中的命令。检查 `skipTests`、`maven.test.skip`、测试排除和“未发现测试”；`BUILD SUCCESS` 不等于测试执行了。
- 字段变更至少核对保存后读取及相关下游；计算覆盖精度和边界；批量覆盖多条、缺关联、失败与必要的重试。
- 单元测试证明算法，真实 SQL 和事务用适当集成设施验证；不以 Mock 数据库证明真实 SQL 正确。
- 分开报告静态检查、编译、执行的测试、接口或数据库验证，以及未执行部分。不要把本地代码存在当成已部署。

需要通用编码、提交溯源或发布判断时，可以配合相应已安装技能；本技能本身不要求安装其他技能。
