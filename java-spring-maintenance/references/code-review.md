# Java 专项代码检查

仅加载与当前改动相关的部分，不据此升级技术栈或展开全项目审计。

## 并发和事务

- Spring 单例 Bean 的可变成员由请求共享；关注缓存、集合、计数器和先判断再修改的竞态。优先局部变量或不可变对象。
- `volatile` 提供可见性，但不能让 `++` 等复合操作原子化。锁、原子类、条件更新或唯一约束按数据范围选择。
- 自己创建或设置的 `ThreadLocal` 在拥有它的边界用 `try/finally` 清理，防止线程池复用时串数据。
- 成功获得锁后进入 `try`，在 `finally` 解锁；多锁固定顺序，持锁期间避免慢外部调用。
- 线程池和异步任务检查队列上限、拒绝策略、异常去向、超时、关闭及上下文传递。不默认用 `parallelStream()` 提速。
- 检查实际事务代理和调用路径：类内自调用可能绕过代理，不能只凭 `@Transactional` 注解认定事务生效。

## 资源和外部调用

- 明确文件流、`Files.lines()`、JDBC 对象和 HTTP 响应的生命周期；适用时用 `try-with-resources`。不要关闭由调用者或框架拥有的共享资源。
- 数据库、HTTP、消息等调用核对超时、连接/响应释放、重试上限和写入幂等性。调度失败不能悄悄终止后续执行，也不能无限堆积任务。

## 输入与权限

- 先证实用户是否能控制输入、能否到达危险操作，以及现有防护是否有效，再认定注入、SSRF、路径穿越或反序列化漏洞。
- SQL 普通值参数化；动态标识符使用白名单。用户提供 URL 时检查实际协议、目标主机和内网访问限制。
- 详情、下载、修改和删除都检查记录级权限，不只检查是否登录。报告区分已确认问题和待验证风险。

## 测试层级

- 纯计算用单元测试；绑定、校验和 JSON 映射用切片或接口测试；真实 SQL、事务及持久化边界用项目集成设施。
- 验证输出、数据库变化和副作用，而不只是验证某方法被调用。按风险覆盖空值、失败、历史记录、并发和重试。
