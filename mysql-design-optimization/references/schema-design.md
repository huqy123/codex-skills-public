# 表结构设计

从真实新增、查询、更新、删除、排序及生命周期出发，先保证唯一性与一致性，再为已证实热点考虑冗余。冗余字段说明权威来源、同步时机和允许延迟。

## 字段和约束

- 主键遵守模块既有生成方式；变更前核对跨系统标识、长度和索引成本。
- 业务唯一性用数据库约束保护，不能只靠先查询再插入。软删除下“可否重新创建”要结合 MySQL 的唯一键与空值语义设计，不机械地把删除标记拼入唯一键。
- 精确数量与金额使用适当 `DECIMAL`，明确范围、小数位及应用舍入。状态、长文本和 JSON 按真实读写与检索需求选择。
- `NULL`、默认值和缺字段的业务含义要清楚。不要用无意义的 `0`、空字符串或当前时间掩盖未处理历史数据。
- 关联字段核对类型、长度、signed/unsigned、字符集和排序规则；避免隐式转换及比较语义不一致。
- 明确采用的引擎、字符集和排序规则，不假定服务器、数据库、连接与表的默认值一致。
- 外键按删除规则、历史数据、同步导入和跨库关系判断，不默认全加或全禁。

## 访问路径

主键和唯一约束之外，索引服务于真实 `WHERE`、`JOIN`、`ORDER BY` 及分页。不能机械地为每个关联字段或布尔状态各建一个索引；结合已有联合索引与基数判断。

输出必要的表关系、字段语义、DDL、唯一与关联策略、访问路径及有意保留的差异，不重复整篇建模教程。
