# 个人编码规范

用最小完整改动解决已确认的问题。沿用项目真实的技术版本、分层、命名、异常和格式习惯；不借机清理无关代码，也不复制已知缺陷。

## 修改前

- 先查看 Git 状态，保留用户已有修改。找到真实入口、写入点和消费者，明确本次允许改变什么。
- 涉及接口、状态、持久化或导出时，追踪输入、业务处理、数据库或快照、再次读取及下游展示。不能只看一个方法就判断链路完整。
- 明确必须保持的字段名、错误格式、状态含义、文件布局和历史记录行为。需要改变这些契约时，先确认需求。

## 实现要求

- 复用已有职责，避免为一次性需求增加通用框架、配置开关或推测性兼容分支。最小改动不是省略必要校验、事务和测试。
- Controller 负责接口映射、绑定、声明式校验、权限和响应包装；业务判断、状态变化、数据访问与事务放在 Service 用例入口。不用 Controller 私有方法隐藏业务逻辑。
- 避免在逐条循环中查询或写库。先批量读取，按业务标识建立映射，再批量写入；大批次可分段，每段仍使用批量 SQL。遗留限制无法消除时，说明位置、规模和风险。
- SQL 普通值使用参数绑定；动态列、排序和表名只来自白名单。空条件、空集合或缺关联不得意外扩大更新范围。
- 多表写入明确事务边界和失败回滚；重试、回调、消息重放明确幂等语义。根据权威数据校验归属、权限、状态和操作资格，不只信客户端。
- 先读后写在写入时保护状态，按实际风险使用条件更新、版本号、唯一约束或已有锁。数据库事务不能让远程 API、消息和文件自动具有原子性，避免慢 I/O 占用长事务。
- 精确十进制业务值使用 `BigDecimal` 或项目对应精确类型，明确单位、小数位和舍入规则。用户可见的批次、导出和历史使用稳定业务排序，并补唯一兜底键。
- 保留异常原因，不吞错后返回成功。日志只记排查所需的标识和阶段，不输出凭证、连接串或不必要的个人信息。
- 注释解释业务原因、参数单位和副作用，不逐句翻译语法。公开用例或复杂状态方法的契约随代码更新。源码保持 UTF-8 无 BOM。

Java、Spring、MyBatis 的分层和精度细节按需读 [Java 后端检查表](references/java-backend.md)。

## SQL 与验证

- 已核实环境、只执行一次的变更，优先直接 DDL/DML、简短注释和核验 SQL；确有重复执行、多环境差异或迁移规范时才增加相应机制。
- DDL、回填、数据修复和索引操作分清预检查、执行、核验和回退；没有明确目标与授权，不执行写入。
- 用同一个聚焦检查展示修改前的问题与修改后的结果。计算检查边界和舍入，保存检查重新读取，批量检查多条、缺值、部分失败和必要的重试行为。
- 编译、实际执行的测试、接口验证和部署事实分开说明。不能把静态阅读或编译成功说成业务全链路通过。

其他技能可按需配合；本技能不依赖特定框架、数据库连接技能或个人环境配置。
