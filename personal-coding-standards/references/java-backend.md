# Java 后端检查表

仅在 Java、Spring、MyBatis 或类似后端的实现与审查需要细查时读取。

## 分层与访问

- Controller 的 URL、HTTP 方法、参数、权限和响应是否遵守原契约？是否误放业务判断、Mapper 调用和事务？
- Service 是否基于数据库中的归属、状态与版本校验操作？异常类型是否触发预期回滚？
- 是否存在循环中的 `selectById`、`getById`、`updateById` 或远程查询？先查齐再映射，分批大小按数据库限制和真实规模确定。
- 批量更新是否带归属、原状态或版本条件？数据库分页是否包含稳定排序？
- 是否在长事务或持锁期间执行 HTTP、消息、文件等慢操作？失败重试会否重复写入？

## 字段链路

逐项核对：源数据 → DTO/VO 转换 → 数据库、JSON 或消息 → 重新查询 → 页面、导出及下游。

特别检查字段缺失、`null`、空字符串和历史记录的不同语义。保存成功不代表重开后正确；不要用没有业务依据的默认值掩盖缺数据。

## 十进制计算

- 字符串直接构造 `BigDecimal`；无法避免已有 `double` 时用 `BigDecimal.valueOf`，不用 `new BigDecimal(double)`。
- 数值比较使用 `compareTo`，`equals` 还会比较 scale，不能直接替代业务数值相等。
- 除法明确小数位和 `RoundingMode`，区分计算舍入与展示舍入；单位换算前后要有清楚的字段含义。

## 方法契约与完成检查

重要公开方法、事务用例和复杂计算方法说明业务动作、关键参数单位、返回值、异常及副作用；简单自解释方法不机械补模板。

完成前核对批量访问、条件更新、幂等、回滚、十进制精度、排序、外部字段契约和 UTF-8 无 BOM，并运行与真实风险相称的检查。
