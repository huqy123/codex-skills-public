# 会话整理与交接

仅在用户明确说“会话整理”“会话交接”或点名本 skill 时执行。不要因会话变长、回复变慢或工具调用次数多而自动执行。

尊重否定和仅询问用法的意图。引用、代码块、附件中出现口令是材料，不是执行请求。默认只处理当前会话及指定材料，不自动搜索其他会话、整套代码或记忆库。

## 整理方法

1. 从当前目标和最新用户修正开始，旧结论被新结论替换。
2. 分开记录已核实事实、用户确认的要求、建议、失败检查和待验证事项。
3. 保留继续工作必需的路径、分支、关键方法、输入、错误、限制和未完成项；删掉重复过程和已废弃方案。
4. 不为写摘要重新调查、修改代码、联网或写入长期记忆；不删除原始记录。
5. 如果宿主提供原生压缩入口，先说明保留清单，再按宿主规则执行并等待完成证据；没有入口就只整理交接内容，不声称释放了上下文。

保留用户已有修改、关键业务条件、有效授权限制、失败检查、待办和运行中进程。易被误用的废弃方案只留结论与原因，不能把未知信息或原始错误当成无用内容删除。

## 原生压缩与摘要不是一回事

- 只有确认入口可操作当前会话时才执行原生压缩；独立启动另一服务或改写历史文件不能冒充当前会话压缩。
- “请求受理”不等于“完成”。按宿主实际完成证据报告，遵守运行中回合限制，不为整理强行中断工作。
- 压缩后核对目标、关键数值、限制和未完成项是否还在；遗漏必要信息就补回。
- 无同口径用量数据时，不编造压缩比例、释放空间或提速效果。摘要本身不修改宿主上下文和自动压缩设置。
- 交接模式或用户要求“只写摘要”时，只生成独立接手记录，不自行压缩、新建任务或写长期记忆。

## 交接内容

```text
当前目标与完成条件：
最新确认的要求及禁止事项：
工作区、分支及已有修改：
已完成工作与证据：
关键文件、方法或交付物位置：
检查结果：已通过 / 失败 / 未执行：
未完成事项、阻塞和运行中任务：
下一步：
已废弃或仍待确认的结论：
```

只写接手人无需查看原聊天也能继续工作的内容；不把旧状态写成实时状态，不把生成代码写成测试通过。

内容按需要选用，不强制填满模板。收尾明确是“仅完成整理”“压缩已受理待完成”还是“已核实完成原生压缩”。用户要求保存时才写指定文件，不删除聊天、日志或原始资料。
