# 任务提速

减少完成整件事的重复工作，不降低业务正确性。用户要求和项目约定优先；本技能不额外要求固定计划文档、框架安装或审批。

## 先确定范围

- 结合当前需求、未完成工作和最新补充，明确本次交付、完成条件和范围。不因最后一条是补充问题就丢弃原任务。
- 只调查时保持只读；需求明确且已授权时才修改。
- 只澄清会改变业务结果的歧义，其余继续推进。已确认的方案不重新从头讨论。
- 新发现只在会影响当前结果时扩大范围；无关问题单独列出。

## 按风险选择检查

- 纯文字或简单展示：读取相关文件，检查格式和受影响的交互。
- 代码问题或测试失败：先用具体输入定位，再做最小修复和回归检查。
- 计算、保存、接口、状态、批量或新旧数据兼容：追踪输入、判断、持久化、重开和下游使用，覆盖正常、失败和边界路径。
- 复杂需求先确认会改变结果的歧义；已确认的方案不重复讨论。
- 发布判断另按发布审查流程，不能用一次编译替代业务验证。

文件数量只是调查起点，不是限制。即使只改一行，只要影响计算、持久化或状态，也按实际风险验证。

## 避免流程叠加

- 每项任务使用一个主要流程。已有项目规范、阶段记录和合格检查直接复用，不为换技能重复执行。
- 已有工作流时沿用相关任务，不迁移或清空无关状态。新任务只有确需跨会话规范或阶段恢复时才考虑相应工具。
- 框架、专用技能和子代理都是按需选项，不默认安装、初始化或全套启动；其使用仍服从用户和宿主的授权要求。
- 独立读取可以并行；依赖上一步结果或修改同一文件时顺序处理。委派确有收益时只提供必要背景，不创建用户任务代替内部协作。
- 可用时结合 `personal-coding-standards`、`java-spring-maintenance`、`mysql-design-optimization` 或 `release-candidate-review`；缺少这些技能时仍按本节风险要求完成必要工作，不将它们视为安装前提。

## 最小修改与验证

- 先看分支、工作区和相关 diff，保留已有改动，不顺手重构。
- 用精确搜索定位符号和调用链，局部读取文件，复用已有检查结果。
- 同一内容首次需要才读；文件、分支、输入或环境变化后只刷新受影响部分。工具输出保留关键证据，不反复倾倒全文。
- 代码和 SQL 交付最小完整实现，不因假设中的未来需求加入框架、通用迁移或大量兼容分支。
- 修改后至少核对最终 diff、格式、语法或类型检查；风险较高时补业务边界测试。
- 报告时区分静态检查、编译、模拟、真实接口和环境联调证据。
- 没有运行过的检查写“未执行”，不要写成通过。
- 验证通过后，只在后续修改影响结果、出现失败或仍有具体疑点时扩大或重跑检查。

## 收尾

说明改了什么、验证了什么、仍有什么限制，以及下一步需要谁在什么环境确认。不要自动提交、合并、推送或修改无关配置。

不承诺固定提速比例，不自动调整模型、插件、记忆或上下文设置；会话变长不等于授权整理或压缩。
